# Практическая работа № 6

Вариант 30 «Карточка задачи». Приложение на Java с двумя XML-экранами.

## Запуск

Откройте проект в Android Studio. Для сборки нужны JDK 21 и Android SDK Platform 37.0, для запуска — устройство или эмулятор с Android API 36 или выше.

```sh
bash ./gradlew :app:assembleDebug
```

## Как проверить

1. Нажмите на иллюстрацию «Как заполнить». Появится подсказка.
2. Нажмите «Рассчитать» с пустым названием или укажите приоритет за пределами 1–3. Ошибка отображается в Snackbar.
3. Введите название, приоритет от 1 до 3 и отметьте «Срочно». «Рассчитать» покажет результат на форме. Приоритет 1 выделяется зелёным, 2 — оранжевым, 3 — красным.
4. Нажмите «Далее». Убедитесь, что на карточке совпадают название, приоритет и срочность.
5. Нажмите «Назад» на экране карточки. Введённые данные сохранятся в форме.

## Ответы на контрольные вопросы

1. Activity обрабатывает события, XML описывает разметку, а идентификаторы `R.id` связывают элементы с кодом. `setContentView` загружает макет и делает его содержимым экрана.
2. `findViewById` ищет элемент по его ID. ViewBinding генерирует класс с типизированными ссылками на элементы. Для него включают `buildFeatures { viewBinding = true }` в модуле приложения.
3. Для `android:onClick` в Java нужен метод Activity вида `public void method(View view)`. Имя в XML должно совпадать с именем метода.
4. Intent описывает действие. Явный Intent указывает конкретный компонент, а неявный указывает действие и данные, по которым Android подбирает обработчик.
5. Второй аргумент `getIntExtra` задаёт значение по умолчанию, когда числовой параметр отсутствует.
6. Если Activity не зарегистрирована в манифесте, запуск через Intent завершится `ActivityNotFoundException`.
7. `finish()` убирает текущий экран из стека и возвращает пользователя к предыдущему экземпляру. Запуск `MainActivity` создаст новый экземпляр поверх существующих экранов.
8. Для возврата результата второй экран вызывает `setResult` и `finish()`. Первый регистрирует получателя через `registerForActivityResult` при создании Activity, поскольку регистрация привязана к её жизненному циклу и должна произойти до перехода в состояние `STARTED`.
